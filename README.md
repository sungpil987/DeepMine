# DEEPMINE 3.0 · 광부의 계승

광물 50종, 광구 5개를 탐험하는 오프라인 Android 채굴 게임. Canvas 게임과 Android WebView 셸로 구성하며 서버·광고·결제는 없습니다.

## 이번 업데이트

- **보스 처치 팝업 제거.** 채굴을 막지 않는 짧은 알림만 표시합니다(10초 이내 반복 표시 억제). 설정에서 완전히 끌 수 있습니다.
- 보스 주기 25→50개, 내구도 4→6배, 연구 결정 보상 3~11→6~18개. 전설/신화 최초 발견만 별도 연출하며 이것도 설정에서 끌 수 있습니다.
- 평생 업적 **9→62개**, 분류 필터·보상 일괄 수령. 채굴·판매·수집·보스·제작·탐사·타격·치명타·환생·심도 목표.
- 매일 갱신되는 임무 3개: 광석 100개, 보스 2회, 판매 5,000 G. 누적 진행도 기준이라 환생으로 일일 임무가 초기화되지 않습니다.
- **환생**: 이번 생 채굴 10,000개 + 실제 광물 판매 12,000,000 G + 별의 심연 개방 시 가능. 영혼석을 얻고 피해·판매가가 환생당 영구 +10%.
- 계승 능력 4종: 피해, 판매가, 다음 생 시작 골드, 자동 작업. 영혼석으로 강화하며 환생 시 유지.
- 마지막 광구의 **심도 도전**: 단계별 채굴 목표와 골드를 달성해 내려갑니다. 심도마다 내구도 ×1.28 / 해당 지역 광물 가치 ×1.18. 현재 심도는 환생 시 초기화, 최고 기록은 유지(최대 200).
- 무인 탐사: 5분·30분·2시간 선택. 현재 지역과 기간에 따라 비용·보상 차등.
- 연구 한도 20→50, 강화 비용·피해 성장·자동 속도·반복 의뢰 보상을 재조정.
- 오프라인 골드는 장비·판매가·광구·심도·영구 능력을 반영한 **예상 자동 판매 수익의 22%**, 최대 4시간. 실제 광물·보스 기록은 오프라인에서 생성하지 않습니다.
- 자동 채굴 시 매 타격마다 저장/DOM 재배치를 하지 않도록 줄여 고속 채굴 부하 완화.

## 환생으로 바뀌는 것

| 초기화 | 유지 |
|---|---|
| 골드·가방·장비 강화 레벨 | 도감·발견 기록·판매 잠금 |
| 광구 개방·현재 심도·광구 내 진행도 | 누적 채굴·판매·보스·최고 심도 |
| 진행 중 탐사·스킬 재사용 시간·보장 카운터 | 연구·연구 결정·드론·폭탄·계승 능력 |
| 이번 생 채굴·판매량 | 업적·수령 기록·출석·일일 임무 |

확인 버튼을 두 번 거쳐야 환생합니다. 확정 직전에 전체 기록을 `deepmine-before-prestige`에 백업하고, 백업 실패 시 환생을 중단합니다. 설정의 **환생 전 백업 불러오기**로 코드를 불러온 뒤 복원 확인을 거쳐 되돌릴 수 있습니다. 다음 환생 시에는 직전 백업이 교체됩니다.

## 밸런스 기준

새 광구 개방 요구는 채굴 100 / 600 / 2,500 / 10,000개, 골드 3,000 / 60,000 / 800,000 / 12,000,000입니다. 이미 개방한 광구는 업데이트로 잠기지 않습니다.

자동 채굴은 장비 레벨당 0.12회/초, 드론당 0.25회/초가 기본입니다. 작업 효율 연구는 레벨당 +6%, 영원의 동력은 레벨당 +8%. 후반 곡괭이는 10레벨 이후 추가 피해 곡선이 붙습니다. 반복 의뢰 보상은 선형 증가 대신 제곱근 증가로 과도한 골드 폭증을 완화했습니다.

`tests/balance.cjs`의 시드 고정 2시간 모형: 초당 2회 또는 7회 입력, 자동 타격, 5초마다 판매·보상 수령, 자동 장비/연구 구입. 세 조건에서 첫 환생 가능 시점은 약 13~22분, 2시간 후 곡괭이 레벨은 71~73이었습니다. **끊김 없는 입력과 즉시 구매를 가정한 모형이며 실제 플레이 시간 보장이 아닙니다.** 환생과 심도는 모형에서 실행하지 않아 장기 목표와 별도로 기본 성장 속도를 검증합니다.

## 저장과 업데이트

기존 `deepmine-v1` 저장 키와 최초 50개 광물 ID를 유지합니다. v1/v2→v3로 골드·가방·도감·강화·연구·드론·광구·현재 광석·업적 수령 기록을 마이그레이션합니다. 진행 중 v2 보스는 늘어난 최대 내구도에 맞춰 남은 체력 비율을 유지합니다. v2에는 없던 판매/타격 통계는 업데이트 이후부터 측정하며, 기존 누적 채굴/보스 기록은 첫 생 기록에 반영합니다. 이전 원본은 `deepmine-before-v3`에 보관합니다.

설정에서 백업 코드 생성·복사·붙여넣기 복원 가능. 복원도 2단계 확인을 거칩니다. 기기 앱 데이터 삭제/앱 삭제 시 백업하지 않은 기록은 사라질 수 있습니다.

APK는 GitHub Actions → 성공 실행 → **DeepMine-APK**에서 받습니다.

- **2.0 separate를 설치한 사용자:** `DeepMine-3.0-separate.apk`를 기존 앱 위에 업데이트. 패키지명 `com.peter.deepmine.v2` 유지, 버전 코드 3.
- 원래 패키지로 2.0을 설치했다면 `DeepMine-3.0-update.apk` 사용. 패키지명 `com.peter.deepmine` 유지.
- 기존 1.0은 다른 임시 서명이어서 덮어설치 불가. 1.0을 지우지 않고 separate APK를 설치하면 원래 앱과 데이터는 남지만 두 앱 사이의 자동 이전은 없습니다.
- 개발 서명 키를 Actions 캐시로 재사용합니다. 키는 저장소에 커밋하지 않습니다. 캐시 유실 이후 동일 서명은 보장되지 않으므로 장기 배포에는 소유자 관리 release 키와 GitHub Secrets 구성이 필요합니다.

## 개발과 검증

JDK 17 / Gradle 8.9 / SDK 35 / Android 8.0 이상. 버전 3.0.0.

```sh
node tests/engine.test.cjs
node tests/balance.cjs
node tests/ui.test.cjs # Playwright + Chromium 필요
# 일반 패키지
 gradle assembleDebug --no-daemon
# 별도 설치 패키지
 gradle assembleDebug -PsideBySide=true --no-daemon
```

엔진 테스트는 25개 시나리오 그룹과 10만 회 추첨을 포함합니다. UI 테스트는 비차단 보스 처치, 62개 업적, 일일 임무, 심도, 환생 확인/취소, 계승 능력, 환생 전 백업, 기존 메뉴, 기록 복원, 320/390/430px 폭을 검증합니다. Actions에서 테스트 통과 후 두 APK를 컴파일합니다. 실제 Android 기기 설치/플레이 확인은 별도입니다.
